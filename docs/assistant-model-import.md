# 自定义角色导入：格式、授权与操作边界

入口：右上角「用户菜单 → 桌面 AI 助手 → 导入 2D / 3D 角色」。内置机器人无需导入，始终可以切回。

## 支持什么

| 类型 | 选择的文件 | 能做什么 | 不会自动获得什么 |
| --- | --- | --- | --- |
| 2D 图片 / 动图 | PNG、GIF、WebP | 透明背景、播放原动图、整体轻摆/跳跃和轻微呼吸 | 自动抠图、骨骼、独立眼动、生成表情 |
| 2D 分层角色 | `.maji2d.json`，图片保持相对目录 | 按声明叠放图层，头部/眼睛/嘴部移动，眼部眨眼，表情替换 | Live2D、Spine、Inochi2D 格式兼容、任意骨骼或物理系统 |
| 3D 角色 | `.vrm`，VRM 0.x / 1.0 | 绑定支持时眼动/表情、程序点头/挥手、待机 | 缺失的人形绑定、缺失表情的自动生成 |
| 通用 3D | 资源内嵌的 `.glb` | 显示几何与材质，播放文件内已有动画 | VRM 眼动、表情、人形挥手或自动绑定 |

本次不支持独立 `.gltf`、FBX、OBJ、Live2D、Spine、Inochi2D、ZIP、HTML、SVG、可执行脚本；不会自动转换这些格式。需要专有运行库的格式，不能因“模型免费”而绕过运行库许可。通用 GLB 朝向由素材决定，未必天然正面朝向相机。

限制：单次角色快照合计128MB，自定义角色最多20个；像素图片每边≤8192且总像素≤3200万。分层包画布≤4096、最多32层/32表情/128张图片，图片合计≤6400万像素。3D最多5000节点、64张图、512个网格及1000万个访问器元素。暂不支持 Draco、Meshopt、KTX2 压缩资源。接近上限仍可能因设备资源不足而加载失败，成功预览不等于长期性能保证。

## 接受哪些授权

“免费下载”只说明获取价格，不等于拥有商业使用、改编或再分发权。导入策略要求：免费获取，并且原许可明确允许商业使用、修改及分享改编作品、再分发。

| 许可 | 接受条件与需保留的内容 |
| --- | --- |
| CC0 1.0 | 填写作者/来源及原始依据；程序仍保留来源以便追溯 |
| CC BY 4.0 | 保留作者、作品、来源、许可链接、必要声明及改动说明 |
| CC BY-SA 4.0 | 保留署名等，并确认对外分享改编素材时遵守相同或兼容许可共享条件 |
| 自定义许可 | 填写原文及许可网址，明确覆盖免费获取、商业使用、改编及再分发；不能用勾选覆盖原文禁令 |

以下不符合此向导范围：NC非商业、ND禁止分享改编、仅个人使用、禁止再分发、作者不明或仅标注“网上免费”。破解/盗取的素材不能通过填写表单变成合法授权。

VRM还可能包含独立的商业、用户范围、改编与再分发设置。本版要求使用范围包含所有人、商业范围包含企业，并允许分享修改后的文件；仅限作者、特定人员或个人营利也不能作为无此限制的模型导入。VRM1省略字段时按官方默认限制处理，不把空值当作许可；`allowModification`仅允许修改，不等于`allowModificationRedistribution`。明确冲突会阻止导入，不能靠修改表单覆盖。若另有作者授权，需取得与之相符的模型/声明再重选。

本功能核对记录完整性和已知内嵌声明冲突，**不联网认证权利人身份、不鉴定许可真伪、不授予任何新权利**。记录明确标为“用户提供的声明，非平台认证”。许可还可能不能覆盖肖像、商标、角色IP和第三方贴图，应分别核对；模型许可也不等于应用或渲染库许可。对外共享素材的义务不自动等于整个码迹应用适用同一许可，实际仍以原文与使用方式为准。

官方参考：[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)、[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)、[CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/)、[VRM1许可字段与默认值](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm-1.0/schema/VRMC_vrm.meta.schema.json)。

## 四步操作

1. **选择类型和文件**：先读该类型能力与限制，再打开本地文件。分层2D包选择描述JSON，不是随意选择整个项目目录。程序会读入不可变快照，后续修改源文件不会偷偷改变本次预览/提交内容；想换文件需返回重选。
2. **检查与预览**：显示大小、文件数、能力说明、SHA-256摘要和内嵌许可字段。预览发生在无Node、无应用接口、禁止外网的隔离页面。明确许可冲突的文件不进行预览，失败/超时不能继续。主进程也校验成功预览，不能直接调用确认接口跳过。可重试或返回换文件；一份快照保留20分钟，超时释放并要求重选。
3. **填写授权记录**：填写作者、原始来源网址或本人原创说明、许可类型、许可原文/依据、署名、改动说明，并逐项确认。BY-SA还需确认共享条件。不能只填“免费”“朋友发的”或点击全选代替核对原文。
4. **确认保存**：核对名称、来源、类型、许可和快照摘要。默认只加入角色库；勾选“导入后立即启用此角色”才自动启用和切换。保存前可返回更正；取消或失败不改变当前角色。

## 导入后

- 本地保存资源副本与 `license-record.json`，角色列表的「来源与授权」可以查看记录、署名、改动和摘要。
- SHA-256对应按资源名排序并包含资源名的导入快照；分层包描述会规范化为安全文件名，因此不保证与原始单文件哈希相同。图片本身不改写，源文件不修改。
- 导入不会自动上传模型、向AI发送模型、替用户发布或把自定义模型加入码迹安装包。以后自己对外发布仍需履行许可义务。
- 这里是显示和陪伴功能，不是网格、贴图、骨骼编辑器。二次开发需要使用适配编辑工具；应用支持导入不等于提供了二次开发所需的源工程。
- 删除只移除本地副本，不修改原文件。即使旧模型缺少/不符合授权记录，也可以从其「来源与授权」直接移除，不必填写不实声明来解锁删除。内置机器人不能误删。
- 旧自定义副本没有记录时保留文件，暂不能选用，回退内置角色；可以补充授权并重新计算摘要后使用。模型和记录位于 userData/assistant，不应把学习笔记备份当作模型备份。

## 分层2D开放格式示例

文件名 `pet.maji2d.json`，所有引用的PNG/GIF/WebP放在该目录内；不允许`../`、符号链接、网址或脚本。图层按数组顺序叠放，不能通过路径执行程序。

```json
{"version":1,"width":600,"height":800,"layers":[{"id":"body","file":"body.png","role":"body","x":100,"y":300,"width":400,"height":500},{"id":"head","file":"head.png","role":"head","x":150,"y":50,"width":300,"height":300}],"expressions":[{"name":"开心","files":{"head":"head-happy.png"}}]}
```

`role`可选`body/head/eyes/mouth/decoration`；有`eyes`图层才提供独立眨眼，表情必须引用已有图层ID。该格式只包含数据和图片，不接受JavaScript或第三方骨骼引擎插件。
